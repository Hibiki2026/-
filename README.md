# 問題ランダム機構

`index.html` と `transfer.js` を同じ場所に静的配信します。

## コードによる引き継ぎ

1. 問題セットを保存したブラウザで、英字と数字を含む半角12〜64文字の専用コードを設定し「コードを登録して保存」。
2. 以後、セット編集、チェック、「必ず出る」、表示問題、残り出題順、周回、答えの表示状態を変更時に自動保存。「今すぐクラウド保存」も使用できます。閉じる前に「クラウド保存済み」を確認してください。
3. 別ブラウザで同じコードを入力し「コードで引き継ぐ」。セットと学習状態を置換します。編集中の未保存セットは先に保存してください。

復元前の端末データは `question_random_mechanism_before_cloud_restore` にバックアップします。従来の長いデータコードとセット共有リンクは維持しています。短いコードを忘れた場合に備え、従来方式でのバックアップも利用できます。

クラウドは既存のMyLinks用Supabaseで、アプリ専用の非公開テーブル `link_base_virtual.question_saves` を使用。`supabase/question-transfer.sql` は適用済みです。問題本文や回答もクラウド保存の対象です。

コードを知る人は読み書きできます。コード原文をサーバーへ送らず、ブラウザでSHA-256化し、サーバーでもアプリ別のハッシュにして照合。IndexedDBには連携用ダイジェストと版番号を保存します。既存のセット保存方法は維持しています。別ブラウザの更新がある場合、古い版の上書きを拒否して同期を停止します。新しいブラウザでは最初にコードで最新データを読み込んでください。

テーブルの直接アクセス・コード列挙は許可しません。コードだけで復元する仕様のため、RPCのanon実行権限は意図的です。既存コードの再登録は拒否します。最大約900KB・500セット・10000問まで。入力コードは英数字（-と_も可）で12文字以上。コード原文や問題データをGitHubへ記録することはありません。

## 検証

`node tests/transfer.cjs`

コード検証、ハッシュ化、保存/復元、チェックと必須問題、学習状態、更新競合の停止をモック通信で確認。DBもanonロールで登録/取得/更新/誤コード/重複/競合をトランザクション内で検証しロールバックしました。公開サイトの実ブラウザ・端末間通信は未確認です。
